Claude Desktop Buddy · Fork Feature

中文语音输入

按住桌面宠物的一个按钮说话，中文自动转写并发给 Claude。

01这是什么

Claude Desktop Buddy 是一只跑在 M5StickC Plus 上的桌面宠物，通过蓝牙陪伴你的 Claude 会话。 这个 fork 给它加了一项能力：把宠物变成一个中文语音输入按钮。

你按住宠物的 B 键对着它说中文，松手后——几秒内，你说的话就 自动变成文字、自动发送到电脑上的 Claude desktop。全程只碰宠物一个键， 转写在本地完成（用阿里 FunASR）， 不依赖联网识别。

一句话 宠物 = 一个对着说中文、自动发给 Claude 的硬件听写按钮。

02工作原理

声音从宠物的麦克风出发，经过四段，落进 Claude 的输入框：

Buddy 麦克风
SPM1423 PDM · 16 kHz / 16-bit
↓IMA ADPCM 4:1 压缩
USB 串口 · 115200
设备 → 电脑，带帧同步
↓Python companion 解码
FunASR
paraformer-zh · 本地离线转写
↓SendInput 注入 Unicode
Claude Desktop 输入框
自动落字 + 自动回车发送

宠物本身跑不动语音模型，所以它只负责采音 + 压缩 + 通过 USB 吐出去； 电脑上一个常驻的小程序（companion）负责转写 + 把中文打进当前窗口。 两件事各司其职。

03你需要什么

项目说明
M5StickC PlusESP32 + 内置 SPM1423 麦克风 + 屏幕 + A/B 按钮。本固件就是为它写的。
一台 Windows 电脑转写和文字注入在电脑上跑。目前 companion 是 Windows 版（用 SendInput 注入）。
Claude desktop语音转出的中文会打进它的输入框。其实打进任何聚焦的输入框都行。
USB-C 数据线烧录 + 运行时宠物都通过它连电脑（音频走这条线）。
uvPython 包管理器，用来跑 companion。首次会自动装好 FunASR / PyTorch 等依赖。
联网（仅首次）FunASR 模型首次约下载 1 GB；之后完全离线运行。

04从零开始安装

这一节假设你电脑上什么都还没装。照着每一步做就行，一共六步： 装三个工具 → 拿到代码 → 烧录固件 → 启动程序。命令都在 PowerShell 里运行（开始菜单搜 “PowerShell” 打开它）。

  1. 装 git（用来下载代码）

    去 git-scm.com 下载 Windows 版安装包， 一路点「下一步」用默认设置装完即可。

    装完关掉再重新打开 PowerShell，输入下面这句确认装好了（能显示版本号就对了）：

    git --version
    不想装 git？ 也可以直接在 GitHub 项目页点绿色的 Code → Download ZIP，下载后解压到一个文件夹。 这样可以跳过这一步和第 4 步的 git clone。

  2. 装 uv（用来跑 Python 程序）

    uv 会自动帮你搞定 Python 和所有依赖，不用你单独装 Python。在 PowerShell 里粘贴运行：

    powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

    装完重开 PowerShell，确认：

    uv --version

  3. 装 PlatformIO（用来烧录固件）

    有了 uv，一句话就能装好烧录工具，它会给你一个 pio 命令：

    uv tool install platformio

    确认（显示版本号即可）：

    pio --version
    如果提示找不到 pio 重开一次 PowerShell；还不行就运行 uv tool update-shell 后再重开。

  4. 拿到这个项目的代码

    选一个放代码的位置（比如桌面），在 PowerShell 里把项目克隆下来，然后进入文件夹：

    git clone https://github.com/gaivrt/claude-desktop-buddy.git
cd claude-desktop-buddy

    如果你第 1 步选了下载 ZIP，就直接解压，然后 cd 进解压出来的文件夹即可。

    之后所有命令 都在这个项目文件夹里运行。PowerShell 标题/路径显示在 claude-desktop-buddy 里就对了。

  5. 把固件烧进宠物

    用 USB-C 数据线把 M5StickC Plus 连到电脑，然后运行：

    pio run -t upload

    首次会自动下载编译工具链（几分钟），之后烧录很快。看到 [SUCCESS] 就成了，宠物会自动重启。

    如果报错「找不到串口 / no serial port」 说明电脑没认出宠物。① 换一根数据线（有些线只供电不传数据）； ② 装 FTDI VCP 驱动（M5StickC Plus 用的是 FTDI 串口芯片，少数 Windows 需手动装）； 装完在「设备管理器 → 端口(COM)」里能看到一个 COM 口就对了。

  6. 启动 companion 程序

    宠物保持连在电脑上。最简单：双击项目文件夹里的 start-voice.bat。

    或者在 PowerShell 里运行（和双击 .bat 等效）：

    uv run --with funasr --with torch --with torchaudio --with pyserial python -u companion/main.py
    首次启动会比较久 程序要下载约 1 GB 的中文识别模型（FunASR），并加载约 50 秒。 请耐心等到出现这一行——看到它就代表准备好了： 
    ready — focus Claude desktop's message box, hold B and talk.
    以后每次启动只加载、不再下载。这个窗口要一直开着，关掉就停了。

    让它开机自动启动（推荐）

    不想每次手动开？让 companion 跟着 Windows 一起启动，开机就在后台待命：

    1. 右键项目里的 start-voice.bat → 发送到 → 桌面快捷方式。
    2. 按 Win + R，输入 shell:startup，回车——会打开 Windows 的「启动」文件夹。
    3. 把刚才桌面上那个快捷方式剪切粘贴进这个「启动」文件夹。

    搞定。下次开机登录后，companion 自动启动。想取消，就把快捷方式从「启动」文件夹里删掉。

    不想每次弹出黑窗口？ 项目里还有个 start-voice-hidden.vbs，它会无窗口地启动 companion。 把上面第 1 步改成给 start-voice-hidden.vbs 建快捷方式即可。 代价是看不到日志——建议先用带窗口的 .bat 确认一切正常，再换成无窗口版。

六步走完，就可以去下一节用起来了。

05怎么用

  1. 切到 Voice 屏

    按宠物正面的 A 键循环屏幕，到 Voice 屏——一个绿色麦克风图标 + ready。

  2. 把光标放进 Claude

    点一下 Claude desktop 的消息输入框，让光标在里面闪（转出的字会落到当前聚焦的窗口）。

  3. 按住 B 说话

    按住宠物右侧的 B 键说中文——麦克风变成橙色并呼吸跳动表示正在录。说完松开。

  4. 自动出字 + 自动发送

    松手约 1 秒后，中文自动出现在输入框，并自动按回车发送给 Claude。一气呵成。

提示 按住即录、松开即发。想要纯打字不发送，可以去掉 companion 里 press_enter() 那一行。

06幕后：三个不显然的决定

如果你想 fork 或调试，这三点值得知道——它们都是踩坑踩出来的。

① 为什么是 115200 + ADPCM，而不是高波特率

实时 16 kHz / 16-bit 音频是 256 kbps，115200 串口扛不住，理论上该用 921600 这类高波特率。但实测下来——这块 M5 的 FTDI 在高波特率下收发全是乱码 （921600、1 Mbaud、160/240 MHz 都试过），只有 115200 稳定可靠。

所以方案是：保留可靠的 115200，把音频用 IMA ADPCM 压成 1/4 （256 kbps → ~64 kbps），正好塞进 115200 的有效带宽，实时无压力。ADPCM 对语音的损失很小， FunASR 识别完全够用。

如果你换了别的板子 高波特率能不能用是硬件相关的。如果你的板子高波特率正常，可以去掉 ADPCM、直接传原始 PCM，更简单。

② 为什么删掉了 BLE HID 键盘

原版 fork 曾用 BLE HID 键盘发 Win+H 触发 Windows 听写。但在 Windows 上， 设备一旦以「键盘」身份广播，系统会把它抢去当 HID 键盘用，挤掉 Claude desktop 需要的 BLE/NUS 连接——表现为「配对成功又立刻掉线」。

本方案根本不需要那个键盘（音频走 USB、文字靠下面的 SendInput），所以直接去掉 HID， 宠物变成纯 NUS 设备，Claude desktop 就能稳定连上了。

③ 为什么文字注入用 SendInput 而不是蓝牙键盘

BLE HID boot keyboard 只能发 US 键位的 keycode，打不出中文。 Windows 上把任意 Unicode 文本注入到聚焦窗口，靠的是 SendInput + KEYEVENTF_UNICODE——这只能由电脑端程序做， 所以 companion 是必须的。

串口帧协议（给改代码的人）

0xAA 0x55 | type(1) | len(2 LE) | payload | checksum(1)
  type:  0x01 REC_START   0x02 AUDIO   0x03 REC_END   0x04 SUBMIT
  AUDIO payload = [predictor:int16 LE][index:uint8] + ADPCM nibbles
  同步字 + 校验和让 companion 能跳过设备打印的调试文本、坏帧自动重同步

07故障排查

现象怎么办
按 B 屏幕没反应确认在 Voice 屏（绿麦克风 + ready），且没在菜单里。麦克风变橙 = 正在录。
录了但不出字看 companion 窗口有没有 ● REC 和转写文本。没有 ● REC = 音频没到电脑：检查 USB 线、确认 companion 连的是宠物那个口。
字落到了别的窗口注入跟随焦点。录完前先点一下 Claude 的输入框，让光标在里面。
companion 启动就退出等它把 FunASR 下载/加载完（首次约 1 GB + 50 秒）。看到 ready 才算就绪。
串口偶尔断companion 自带自动重连，断了会等宠物回来。USB 线接触不良也会掉，插紧。
Claude desktop 连不上宠物这是另一条独立的蓝牙链路（和语音无关）。语音只走 USB，不需要这条蓝牙连接也能用。
